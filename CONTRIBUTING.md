
# Contributing to KeyRush

First of all, thank you for your interest in contributing to **KeyRush**!

KeyRush is an open-source typing speed test project. Contributions, improvements, bug fixes, and feature suggestions are welcome.

## Getting Started

Before contributing, make sure you have:

- Git installed.
- A modern web browser.
- A code editor such as VS Code.
- Basic knowledge of HTML, CSS, and JavaScript.

## How to Contribute

### 1. Fork the Repository

Fork the KeyRush repository to your GitHub account.

### 2. Clone the Repository

```bash
git clone https://github.com/YOUR-USERNAME/KeyRush.git
```

### 3. Open the Project

```bash
cd KeyRush
```

Open the project in your preferred code editor.

### 4. Create a Branch

Create a separate branch for your changes.

```bash
git checkout -b feature/your-feature-name
```

Examples:

```bash
git checkout -b feature/custom-paragraphs
git checkout -b fix/wpm-calculation
```

### 5. Make Your Changes

You can contribute by:

- Fixing bugs.
- Improving typing speed calculations.
- Adding new typing paragraphs.
- Improving the user interface.
- Optimizing performance.
- Improving mobile responsiveness.
- Adding new typing modes.
- Improving documentation.

### 6. Test Your Changes

Before submitting your contribution:

- Check that existing features still work.
- Test typing calculations.
- Check different screen sizes.
- Fix console errors.
- Make sure there are no unnecessary files.

### 7. Commit Your Changes

Use clear and meaningful commit messages.

```bash
git add .
git commit -m "Add custom paragraph mode"
```

### 8. Push Your Changes

```bash
git push origin feature/your-feature-name
```

### 9. Create a Pull Request

Go to your forked repository on GitHub and create a Pull Request.

Explain:
- What you changed.
- Why you made the changes.
- How you tested them.

Wait for review before your changes are merged.

---

## Contribution Guidelines

Please follow these guidelines:

- Keep the code clean and readable.
- Use meaningful variable and function names.
- Avoid unnecessary dependencies.
- Maintain the existing project structure.
- Do not submit copied or copyrighted content without permission.
- Keep the interface simple and user-friendly.
- Make sure new features work properly.
- Avoid unrelated changes in a pull request.

## Reporting Bugs

If you discover a bug:

1. Check whether the issue already exists.
2. Open a new GitHub Issue.
3. Provide a clear description.
4. Include steps to reproduce the problem.
5. Attach screenshots if necessary.

## Suggesting Features

Have an idea for KeyRush?

Open a GitHub Issue and include:

- Feature name.
- What the feature does.
- Why it would be useful.
- How you think it should work.

## Code of Conduct

Be respectful and professional.

- Respect other contributors.
- Accept constructive feedback.
- Avoid spam and unnecessary arguments.
- Keep discussions friendly and productive.

## Questions?

For questions or suggestions, open a GitHub Issue or contact the project maintainer.
