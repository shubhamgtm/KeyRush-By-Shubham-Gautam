
# Security Policy

## KeyRush Security

Security is important to the KeyRush project. We appreciate responsible reports from developers and users who help us identify and fix security vulnerabilities.

## Supported Versions

The following versions are currently supported with security updates.

| Version | Supported |
|---|---|
| 1.0.x | Yes |
| Below 1.0 | No |

## Reporting a Vulnerability

If you discover a security vulnerability in KeyRush, please report it responsibly.

**Please do not:**
- Publicly disclose an unpatched vulnerability.
- Exploit vulnerabilities to access other users' data.
- Upload malicious files or harmful code.
- Attempt to disrupt the service.

### How to Report

Please contact the project maintainer:

- GitHub: https://github.com/shubhamgtm
- Repository: https://github.com/shubhamgtm/KeyRush

If GitHub Private Vulnerability Reporting is enabled, you can also use the repository's **Security → Report a vulnerability** option.

### Include the Following Information

- Description of the vulnerability.
- Steps to reproduce the issue.
- Potential security impact.
- Screenshots or proof of concept, if available.
- Suggested fix, if known.

## Response Process

After receiving a valid report:

1. The report will be reviewed.
2. The vulnerability will be investigated.
3. A fix will be developed when necessary.
4. A security update will be released.
5. The reporter may be credited with permission.

## Scope

Security reports may include:

- Cross-Site Scripting (XSS).
- Cross-Site Request Forgery (CSRF).
- Insecure handling of user input.
- Dependency vulnerabilities.
- Data exposure.
- Authentication and authorization issues, if applicable.

## Responsible Disclosure

Please give the maintainer reasonable time to investigate and fix reported vulnerabilities before making them public.

We appreciate responsible security research and contributions.
